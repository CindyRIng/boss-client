## 2. 鉴权与安全

- REST 仅监听 `127.0.0.1`（`BOSS_HOST`）；除 `/v1/health` 外均需 `Authorization: Bearer <BOSS_API_TOKEN>`。
- `BOSS_API_TOKEN` 默认 `change-me`，部署时必须修改；支持配置文件/env。
- 登录相关接口（`/v1/session/login*`）额外约束：
  - 仅 loopback；单活跃 loginId；TTL 10 分钟；
  - 二维码/验证码截图仅内存或临时文件（600 权限，TTL 删除），不写长期日志；
  - 响应中的 `qr.pngBase64` / `captcha.*Base64` 不回显到日志；调用方自行负责展示与销毁。
- 凭据：手机号从 `BOSS_PHONE` 或 600 权限配置文件读取；不硬编码、不写日志、不写入响应（只返回掩码）。
- 单实例：同一 `profileDir` 只允许一个进程（`.boss-client.lock`，pid 存活检测）。
- 日志脱敏：手机号、验证码、cookie、token、QR 内容、`securityId`（日志中截断/哈希）。
- 只读：不提供沟通/投递/简历/招聘者切换接口。

| `FORBIDDEN` | 403 | 否 | 无权限/账号受限 |
| `NOT_FOUND` | 404 | 否 | 岗位/公司/资源不存在 |
| `QUERY_EXPIRED` | 410 | 否 | queryId 过期 |

## 5. 分页、queryId、refresh、限频、缓存

### 5.1 分页与 queryId

- 搜索/翻页以 `queryId` 为锚点：`q_<yyyymmdd>_<rand>`。
- 服务端在 SQLite `queries` 保存搜索条件（keyword/cityCode/pageSize/已抓页/resCount/totalCount/hasMore），默认 TTL 24h。
- `search.jobs` 返回 `queryId`；`jobs.list` / `companies.list` 使用该 `queryId`。
- `page` 从 1 开始；`pageSize` 1–100，默认 15。
- 上游 `pageSize` 实测默认 15；`totalCount` 可能是展示上限（实测 300），**不代表全集**；以 `resCount` + `hasMore` 判断。
- `pagesAvailable = ceil(resCount / pageSize)`，用于提示可翻页数；`pagesFetched` 为当前 query 已抓页数。
- `companies.list` 的 `total` 是**去重后公司数**，不是岗位数。

### 5.2 refresh 语义

- 读接口默认走 TTL 缓存；`refresh=true` 强制请求上游并写回缓存。
- 搜索：`refresh=true` 重建 queryId（新查询）；`jobs.list` 的 `refresh=true` 只刷新该页。
- 详情：`refresh=true` 绕过对应详情缓存。
- `meta.cached=true` 表示本次结果来自缓存；强制刷新时 `cached=false`。

### 5.3 重试与限频

- 可重试：`AUTH_REQUIRED`、`CAPTCHA_*`、`SMS_CODE_INVALID`、`SMS_RATE_LIMITED`、`RATE_LIMITED`、`TIMEOUT`、`UPSTREAM_UNAVAILABLE`。
- 客户端建议指数退避（1s/2s/4s，最多 3 次）；`RATE_LIMITED` 使用 `details.retryAfterMs`。
- 服务端默认限频：
  - 上游请求 **12 次/分**（令牌桶，容量 3）；
  - 单并发，同一时刻只允许 1 个上游请求；
  - 页间延迟 2.5–4s 抖动；
  - 单次任务最多 5 页（`search.jobs.pages` / `fetchPages` 上限 5）；
  - `code37` → 冷却 60s + 重试 1 次；仍失败返回 `UPSTREAM_BLOCKED`，`status.risk.cooldownUntil` 可见。
- 禁止对同一账号并行发起多个搜索/详情任务。

### 5.4 缓存 TTL（默认，可配）

| 数据 | TTL |
| --- | --- |
| queries | 24h |
| jobs（岗位列表行） | 2h |
| job_details | 12h |
| companies（公司摘要） | 7d |
| company_details | 7d |
| company_jobs | 2h |

## 7. 操作规范

> 所有操作返回 envelope；以下只列 `data`。CLI/MCP 与 REST 同 schema。

### 7.1 health.get

- 鉴权：无。
- 只读、幂等。
- 请求：无。
- 响应：见 6.7。
- 用途：进程/浏览器存活、登录态概览。

### 7.2 status.get

- 鉴权：Bearer。
- 只读、幂等。
- 请求：无。
- 响应：见 6.7。
- 说明：登录态 + 会话 + 风控冷却 + 请求计数 + 缓存；无 quota。

### 7.3 session.login.start

- 鉴权：Bearer。
- 副作用：打开/复用 headful 浏览器；可能发送短信。
- 请求：

```json
{ "mode": "sms", "phone": "15600000000" }
```

`phone` 可选；缺省用 `BOSS_PHONE`。`mode` 可选：缺省时按配置选择（`BOSS_HEADLESS=true` → `qr`，否则 `sms`）。

- 响应：`LoginSession`（见 6.8）。
- 行为：
  - 若当前已登录：直接返回 `state=logged_in`，不打开浏览器（幂等，便于调用方重试）。
  - `sms`：切到验证码登录 → 填手机号 → 点击发送 → 若出现极验则返回 `state=awaiting_captcha`（这是正常状态，不是错误；`captcha` 字段带截图/主图/提示图）；否则 `state=awaiting_sms_code`。
  - `qr`：切到扫码登录 → 抽取 `.qr-code-box img` 的 blob → `qr.pngBase64`；`state=awaiting_scan`。
- 错误：`LOGIN_IN_PROGRESS`（已有活跃 loginId）、`SMS_RATE_LIMITED`。
- 说明：同一时刻只允许一个 loginId；TTL 10 分钟；二维码模式可在 headless 下抽取 Base64 扫码；短信/极验阶段需要 DISPLAY（Wayland/X11 或 Xvfb）。

### 7.4 session.login.get

- 鉴权：Bearer。
- 请求：路径 `loginId`。
- 响应：`LoginSession`；QR 模式可返回刷新后的 `qr.pngBase64`。
- 错误：`LOGIN_EXPIRED`。

### 7.5 session.login.captcha

- 鉴权：Bearer。
- 请求（click）：

```json
{
  "kind": "click",
  "points": [
    { "x": 0.683, "y": 0.625 },
    { "x": 0.173, "y": 0.541 }
  ]
}
```

- 请求（slider）：

```json
{ "kind": "slider", "offsetRatio": 0.63 }
```

- 响应：`LoginSession`；成功则进入 `awaiting_sms_code`（或 `logged_in`，若此前已提交过码）。
- 错误：`CAPTCHA_INVALID`（`details.captcha` 为新 challenge）、`LOGIN_EXPIRED`。
- 说明：`points` 坐标归一化到 captcha.image；顺序必须与提示一致。

### 7.6 session.login.sms

- 鉴权：Bearer。
- 请求：

```json
{ "code": "123456" }
```

- 响应：`LoginSession`；成功 `state=logged_in`。
- 错误：`SMS_CODE_INVALID`、`CAPTCHA_REQUIRED`（登录时再次出现验证码，`details.captcha`）、`SMS_RATE_LIMITED`、`LOGIN_EXPIRED`。
- 说明：登录成功后保存 profile/storage state；不返回 cookie/token。

### 7.7 session.login.cancel

- 鉴权：Bearer。
- 请求：路径 `loginId`。
- 响应：`{ "loginId": "...", "state": "cancelled" }`。
- 说明：关闭 headful 浏览器/释放 loginId；不影响已登录会话。

### 7.8 search.jobs

- 鉴权：Bearer。
- 只读、幂等（同一条件可重复）。
- 请求：

```json
{
  "keyword": "外贸",
  "cityCode": "101090100",
  "page": 1,
  "pageSize": 15,
  "pages": 1,
  "refresh": false
}
```

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| keyword | 是 | — | 岗位关键词 |
| cityCode | 否 | 配置默认 | 城市数字码；多城市可配 |
| page | 否 | 1 | 起始页 |
| pageSize | 否 | 15 | 1–100 |
| pages | 否 | 1 | 本次抓取页数，1–5 |
| refresh | 否 | false | 绕过缓存 |

- 响应：

```json
{
  "query": { "queryId": "q_...", "keyword": "外贸", "cityCode": 101090100, "cityName": "石家庄", "pageSize": 15, "pagesFetched": 1, "resCount": 450, "totalCount": 300, "hasMore": true, "fetchedAt": "..." },
  "jobs": [ "JobSummary..." ],
  "companies": [ "CompanySummary..." ],
  "pagination": { "page": 1, "pageSize": 15, "total": 450, "hasMore": true, "pagesFetched": 1, "pagesAvailable": 30 }
}
```

- 行为：先导航搜索页建立同源上下文；页面内 `POST /wapi/zpgeek/search/joblist.json`；按页抓取（`pages` 页，页间延迟）；写入 queries/jobs/companies 缓存；`companies` 为已抓页去重结果。
- 错误：`AUTH_REQUIRED`/`SESSION_EXPIRED`、`UPSTREAM_BLOCKED`（code37，含 cooldownUntil）、`UPSTREAM_CHANGED`、`TIMEOUT`、`RATE_LIMITED`。

### 7.9 jobs.list

- 鉴权：Bearer。
- 请求：`queryId`（必填）、`page`（默认 1）、`pageSize`（默认 15）、`refresh`。
- 响应：

```json
{
  "query": { "...": "SearchQuery" },
  "jobs": [ "JobSummary..." ],
  "pagination": { "page": 2, "pageSize": 15, "total": 450, "hasMore": true, "pagesFetched": 2, "pagesAvailable": 30 }
}
```

- 行为：按 queryId 取条件；未抓过的页请求 1 页；更新缓存。
- 错误：`QUERY_EXPIRED`、`AUTH_REQUIRED`、`UPSTREAM_BLOCKED`。

### 7.10 jobs.detail

- 鉴权：Bearer。
- 请求：`jobId` 或 `securityId`（至少一个）；`lid`、`refresh` 可选。

```json
{ "jobId": "9b480e5d72caccd303Zz3du6FFFS", "refresh": false }
```

- 响应：`JobDetail`（见 6.2）。
- 行为：
  - 有 `securityId`：直接详情 API。
  - 只有 `jobId`：打开 `/job_detail/<jobId>.html`，从页面 JS/DOM 提取 `securityId`，再请求详情 API。
- 缓存：12h；`refresh` 绕过。
- 错误：`NOT_FOUND`、`UPSTREAM_BLOCKED`、`UPSTREAM_CHANGED`、`AUTH_REQUIRED`。

### 7.11 companies.list

- 鉴权：Bearer。
- 请求：`queryId`（必填）、`page`（默认 1）、`pageSize`（默认 20）、`fetchPages`（0–5，默认 0）、`refresh`。
- 响应：

```json
{
  "query": { "...": "SearchQuery" },
  "companies": [ "CompanySummary..." ],
  "pagination": { "page": 1, "pageSize": 20, "total": 16, "hasMore": false, "pagesFetched": 1, "pagesAvailable": 30 }
}
```

- 行为：从已抓岗位按 `companyId` 去重；`fetchPages` 先补抓页；`matchedJobs` 最多 10 条；公司摘要 7d 缓存。
- 说明：`pagination.total` 为去重公司数；`pagesFetched`/`pagesAvailable` 指岗位页，不是公司页。
- 错误：`QUERY_EXPIRED`、`AUTH_REQUIRED`、`UPSTREAM_BLOCKED`。

### 7.12 companies.detail

- 鉴权：Bearer。
- 请求：`companyId`（`encryptBrandId`，必填）、`refresh`。
- 响应：`CompanyDetail`（见 6.4）。
- 行为：打开 `/gongsi/<companyId>.html`；DOM 提取公司资料 + 工商信息 + 热招 + 招聘者 + 福利；写入 company_details 缓存（7d）。
- 错误：`NOT_FOUND`、`AUTH_REQUIRED`、`UPSTREAM_BLOCKED`、`UPSTREAM_CHANGED`。

### 7.13 companies.jobs

- 鉴权：Bearer。
- 请求：`companyId`（必填）、`refresh`（可选）。公司职位页当前一次返回全部职位。
- 响应：

```json
{
  "companyId": "d6c15290231e61e21Hd70965EFY~",
  "jobCount": 11,
  "jobs": [ "CompanyJob..." ],
  "truncated": false
}
```

- 行为：打开 `/gongsi/job/<companyId>.html`；DOM/内嵌 JS 提取全部职位；如页面内嵌 `securityId` 一并返回；写入 company_jobs 缓存（2h）。
- 说明：若页面因 APP 限制只展示部分，`truncated=true` 并在 `meta.warnings` 说明。
- 错误：`NOT_FOUND`、`AUTH_REQUIRED`、`UPSTREAM_BLOCKED`。

### 7.14 cities.list

- 鉴权：Bearer。
- 请求：`refresh`（可选）。
- 响应：

```json
{
  "cities": [
    { "cityCode": "101090100", "cityName": "石家庄", "province": "河北", "isDefault": true },
    { "cityCode": "101010100", "cityName": "北京", "province": "北京", "isDefault": false }

  "updatedAt": "2026-11-11T12:00:00+08:00"
```

- 行为：内置常用城市 + BOSS 城市接口刷新；7d 缓存。
- 说明：`cityCode` 对外用字符串，内部转数字；避免中文城市名直接拼 URL。

### 7.15 cache.stats

- 鉴权：Bearer。
- 请求：无。
- 响应：见 6.9。

### 7.16 cache.clear

- 鉴权：Bearer。
- 请求：query 参数

```text
DELETE /v1/cache?scope=all
DELETE /v1/cache?scope=expired
DELETE /v1/cache?scope=all&prefix=q_20261111_
```

`scope`: `all` / `expired`；`prefix` 可选（按 queryId/jobId/companyId 前缀清理）。

- 响应：

```json
{ "deleted": { "queries": 3, "jobs": 45, "jobDetails": 2, "companies": 16, "companyDetails": 1, "companyJobs": 11 }, "dbPath": "~/.boss-client/cache.db" }
```

## 8. CLI 命令

```bash
# 健康/状态
boss health
boss status

# 登录（headless 默认二维码；--sms 需 headful）
boss login --sms [--relay]          # headful；--relay 时输出截图/等待 REST 中继
boss login --qr [--relay]           # headful + 终端二维码
boss login status <loginId>

boss login sms <loginId> --code 123456
boss login cancel <loginId>

# 搜索/翻页
boss search jobs --keyword 外贸 --city 101090100 --page 1 --page-size 15 [--pages 1]
boss jobs list --query-id q_20261111_ab12cd --page 2

# 详情
boss jobs detail --job-id 9b480e5d72caccd303Zz3du6FFFS
boss jobs detail --security-id <securityId> --lid <lid>

# 公司
boss companies list --query-id q_20261111_ab12cd --page 1 --page-size 20 [--fetch-pages 1]
boss companies detail --id d6c15290231e61e21Hd70965EFY~
boss companies jobs --id d6c15290231e61e21Hd70965EFY~

# 城市/缓存
boss cities list [--refresh]
boss cache stats
boss cache clear --all
boss cache clear --expired

# 服务
boss serve --port 8790
boss mcp
boss docs [operationId]
```

- CLI 默认输出 envelope JSON；`--format table` 可选。
- `--help` 由 operations + zod 生成。
- `--relay` 模式不依赖本机 GUI：输出 QR/验证码截图路径 + 等待命令输入；适合远程 agent。

## 10. SKILL 草案

`skills/boss/SKILL.md` 目标：

1. `status` 预检：未登录则 `login --sms` / `--qr`，或按 REST 中继等待人工。
2. 搜岗位：`search jobs --keyword 外贸 --city 101090100`。
3. 拿公司：`companies list --query-id ...`，按 `jobCount`/行业/规模筛选。
4. 看公司：`companies detail --id ...`（工商信息 + 热招）。
5. 看岗位：`jobs detail --job-id ...`（描述/要求/招聘者）。
6. 汇总：输出 JSON/表格（不落文件；调用方决定）。
7. 约束：只读；单次 ≤5 页；不并发；遇 `UPSTREAM_BLOCKED`/`needs_human` 停止并提示。

```sql
  company_id TEXT NOT NULL,
  job_id TEXT NOT NULL,
  payload_json TEXT NOT NULL,
  fetched_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  PRIMARY KEY (company_id, job_id)
);

CREATE TABLE IF NOT EXISTS meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- `payload_json` 存对应模型的 JSON；不存 raw 响应/HTML。
- 所有时间 ISO8601；`expires_at` 用于 `cache clear --expired`。
- WAL 模式；单写者；启动时执行 schema 迁移。

## 13. 日志

JSON Lines，示例：

```json
{"ts":"2026-11-11T12:00:00.000+08:00","level":"info","requestId":"req_...","op":"search.jobs","cached":false,"upstreamMs":820,"errorCode":null,"message":"keyword=外贸 city=101090100 page=1"}
```

脱敏规则：
- 手机号 → `156****75`；验证码 → `***`；
- cookie/token/QR 内容不记录；
- `securityId` 只记录长度/哈希前缀；
- 公司名/岗位名可记录（业务数据）。

## 14. 已知限制 / 下一步

1. **极验不可自动破解**：登录必须人工/中继；全自动首次登录不在 v1 范围。
2. **会话 TTL 不固定**：实测约 10.6 天；以 `status.session.expiresAt` 为准。
3. **无岗位发布时间**：`published_at` 缺失，用 `firstSeenAt/lastSeenAt`。
4. **`totalCount` 是展示上限**：不能当全集；以 `resCount`/`hasMore` 为准。
5. **公司职位页可能截断**：`companies.jobs.truncated` 标识。
6. **`securityId` 短时效**：优先用 `jobId`；过期后重新搜索/打开岗位页。
7. **`/gongsi/` 公司大全**：v1 不实现；v2 候选。
8. **高级筛选**：v1 不实现；接口字段保留。
9. **MCP 传输**：v1 stdio；本地 HTTP 后续可加。
10. **多账号**：v1 单账号；架构预留（独立 profile/端口/cache）。
